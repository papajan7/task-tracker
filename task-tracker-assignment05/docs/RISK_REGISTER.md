# Risk Register

Scoring: likelihood and impact are each 1 (low) to 3 (high); score = likelihood × impact. Scores describe the preserved baseline unless stated otherwise.

| ID | Category | Cause / event / consequence | Component and evidence | Classification | L | I | Score | Mitigation / owner / verification | Residual risk |
|---|---|---|---|---|---:|---:|---:|---|---|
| R-01 | Correctness | Blank titles can be stored, creating unusable tasks and clutter. | `baseline/app/service.py:add_task` passes title directly to `Task`; baseline model has no validation. | Confirmed by source inspection; behavior is deterministic. | 3 | 2 | 6 | Validate and trim title in final `Task.create`; owner: project maintainer; verify with whitespace/empty-title unit tests. | Low: validation is local to this CLI; imported malformed legacy JSON is not fully normalized. | 
| R-02 | Correctness | Arbitrary status values can be persisted and displayed, breaking status-based ordering/filters. | `baseline/app/service.py:update_status` assigns the supplied string directly. | Confirmed by source inspection. | 2 | 2 | 4 | Restrict statuses to the three documented values in final service and CLI; verify invalid-status regression test. | Low: hand-edited JSON can still contain an unknown status; file schema migration is out of scope. |

## Priority corrective actions

1. **R-01 / R-02 grouped input and domain validation (score 6 and 4):** reject blank titles, reject unknown statuses, and return explicit errors for missing task IDs. Implemented in `app/models.py` and `app/service.py`; regression coverage is in `tests/test_task_tracker.py`.
2. **R-03 atomic persistence (score 6):** save to a temporary file in the same directory, flush it, then use `os.replace`. Implemented in `app/storage.py`; tested through a real save and a mocked call assertion. A power-loss/crash simulation was not performed.

R-04 is addressed as the single focused structural refactoring. R-05 and R-06 are addressed by repository instructions and the test suite.
